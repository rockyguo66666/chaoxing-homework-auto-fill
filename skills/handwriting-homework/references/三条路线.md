# 路线的取舍

## 对比

| | 0 现成手写体 | A 按需采样 | B 常用部件表 | C FontDiffuser |
| --- | --- | --- | --- |
| 用户要写字 | **0** | 答案里用到的字（150–400） | 320（一次，永久复用） | 100–300（风格参考） |
| 成品来源 | 某个现成字体 | **100% 真迹** | 真迹 + 部件拼接 | AI 生成 |
| 机器要求 | 无（几十秒出图） | 无（本机 1 分钟内跑完） | 无 | GPU / 数小时 / 数 GB 权重 |
| 新字怎么办 | 本来就有 | 补写 | compose.py 拼 | 直接生成 |
| 风险 | 不是本人的字 | 无 | 拼接字结构可能别扭 | 环境装不起来、字结构崩坏 |
| 本机验证 | ✅ list_fonts + 样张已生成 | ✅ 端到端跑通（selftest） | ✅ 拼接链路已测 | ❌ 从未跑通 |

---

## 怎么选

**用户嫌自己字丑 / 不想写采样纸 → 走 0。** 直接列本机手写体候选给他挑，零采样。
但要如实说明：这不是他的字迹。对"字丑但作业要交"的场景，这是最务实的取舍。

**用户愿意写 → 默认 A。** 简答题的答案文本是已知的，直接把用到的那批字写一遍就行——
写字量和 B 差不多，但出来的是真迹，还没有任何"这字不是你写的"的风险。

**要长期用就 B。** 用户如果希望"以后随便写什么都像自己"，让他按 `assets/常用部件表.txt`
写一次 320 字，之后遇到没写过的字用 `compose.py` 拼。
提醒他：拼出来的字结构会有点生硬（部件按固定比例摆放，没有书法上的避让与收放），
但比楷体顶替像得多。

**C 只在明确需要 3500 字全覆盖时才考虑。** 详见 `FontDiffuser路线.md`（本机未验证）。
不要对用户承诺"能生成一整套和你一模一样的字库"——少样本字体生成的质量，通常明显低于真迹。

---

## 混合使用

实际操作里最常见的是 A + 部件拼接：

1. 按 A 写答案里的字（约 90% 覆盖）；
2. 剩下的字用 `fetch_ids.py` + `compose.py` 拼；
3. 拼不出来的（部件也没写过）用楷体顶替，并在报告里点名。

这样用户只需要写一次，且报告能如实说明每个字的来源。

# 踩坑记录（都是本机实测踩出来的）

按"如果不知道会浪费多久"排序。

## 1. 采样纸的表头压在网格上 → 第一行所有字全废

**症状**：切字 IoU 平均只有 0.72，最低 0.12，而且集中在第一行的字（定/顿/一/律…）。

**排查过程**：逐格 dump 二值化后的连通块，发现每个格子顶部都有十几个 2–4px 高的小碎片，
横着排一排——那是说明文字"（四角黑块必须入镜）"被画在了网格第一行上。

**根因**：`make_template.py` 里表头是相对网格顶边定位的（`y0 - head_size*0.95`），
当页数少、网格垂直居中偏下时，说明文字正好落在第一行格子顶部。灰度 150 远低于二值化阈值。

**修复**：表头改成相对页面定位，且断言 `head_top + head_block <= y0`。
改完 IoU 从 0.72 → 0.84。

**教训**：模板上任何深色元素都必须离可写区域足够远，或者足够浅。

## 2. 田字格线的灰度太接近二值化阈值

**症状**：切出来的字被"撑满整格"，宽高比明显不对（原本瘦高的"定"变成方的）。

**根因**：格线原来是 (196,202,208) ≈ 0.78 灰，而阈值是 `bg - drop = 0.98 - 0.20 = 0.78`，
**正好卡在边界上**。扫描件里勉强不越界，一拍照模糊就整段变墨。

**修复**：格线改 (224,228,234)，字模改 (234,234,238)，安全余量从 0.00 拉到 0.10+。
另外在 `preprocess.py` 加了 `drop_rule_remnants()` 兜底：
丢掉"横贯整格且厚度 ≤ 4px"的连通块。

**教训**：辅助线与判定阈值之间至少留 0.08~0.10 的灰度余量。

## 3. raw.githubusercontent.com 在本机不可达

**症状**：`curl` 拉 cjkvi-ids 的 ids.txt 超时（Operation timed out after 45s）。

**修复**：`fetch_ids.py` 按顺序试多个镜像，**jsDelivr 可用**：

```
https://cdn.jsdelivr.net/gh/cjkvi/cjkvi-ids@master/ids.txt   ← 实测 200，2.1MB
```

**教训**：凡是拉 GitHub raw 的地方都准备镜像链。

## 4. macOS 的楷体/手写体不在 /System/Library/Fonts

**症状**：`ls /System/Library/Fonts | grep Kaiti` 什么都没有。

**真相**：按需下载的中文字体在
`/System/Library/AssetsV2/com_apple_MobileAsset_Font7/<hash>.asset/AssetData/`
里，包含 `Kaiti.ttc / Hanzipen.ttc / Hannotate.ttc / Xingkai.ttc / Baoli.ttc / Libian.ttc` 等。

**修复**：`handlib._font_search_roots()` 会把所有 `com_apple_MobileAsset_Font*` 的
`AssetData` 目录加进搜索路径。

## 5. 裂缝跟随的转向规则：必须"尽量右转"

**问题**：把掩码转轮廓时，如果在对角接触的顶点上"左转"，两个对角相邻的墨块会被连成
自相交的八字形轮廓，TrueType 填充时会出现空洞或溢出。

**选择**：转向优先级 = [右转, 直行, 左转, 掉头]，即尽量右转。
这样对角接触的墨块各走各的轮廓，各自都是简单多边形，非零环绕填充出来的并集与原始掩码一致。

实测：147 个 HanziPen 字形，反渲染回读平均 IoU 0.958。

## 6. 抽稀容差的性价比

| eps | 平均 IoU | 体积 |
| --- | --- | --- |
| 1.1 | 0.958 | 124 KB / 147 字 |
| 0.8 | 0.963 | 241 KB |
| 0.6 | 0.969 | 388 KB |

**结论**：默认 1.1。再细只换来 1% 的 IoU，体积翻倍。
（不引入 vtracer/potrace 也够用：直线多边形 + RDP 在 512 尺度下肉眼看不出区别。）

## 7. 其他的小坑

- `random.Random` 没有 `.random(shape)`（那是 numpy 的 API）；
  纸纹生成用 `np.random.default_rng()`，逐字抖动用 `random.Random` 都行，别混着写。
- 沙箱下 `py_compile` 会试图写 `~/Library/Caches/com.apple.python/` 而失败；
  做语法检查用 `compile(open(f).read(), f, 'exec')`。
- `PIL` 11 里 `Image.fromarray(..., mode="RGB")` 的 `mode` 参数已弃用，去掉即可。
- 中文文件名在 macOS 上没问题，但标点做文件名有风险——`preprocess.py` 对非字母数字字符
  统一用 `u002C` 这种码点命名。
- 用 `answer_sheet.py` 渲染"题目+答案"时，题干里的字往往没写进采样纸，
  会有一批字走楷体顶替。**这是正常的**，报告里会写明；想要全真迹就让用户只写答案、
  题干留空（`--with-question` 不开）。

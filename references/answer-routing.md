# 题型分流细则

## 为什么分流

答题框的输入方式决定可读性和可核查性：

- **选择题**：直接点选，答案本身就是字母，没有歧义空间。
- **物理/数学解答题**：步骤有强推导链，手写图片能保留公式排版和推导痕迹，也更接近手写答题的观感。
- **其他长解答题**：步骤超过 1000 字时手写图片反而难读、难核对，直接打字更合适。

## 判定顺序

```
是选择/判断题？          → 点选（cx mixed 的 choices.json）
是物理或数学类的解答计算题？ → 手写答题纸图片（不分字数）
其余解答/填空题：
    步骤字数 ≤ 1000？     → 手写答题纸图片
    步骤字数 > 1000？     → 直接打字（cx fill）
```

「步骤字数」= 准备写进答题框的答案正文字符数，不含题干复述。

## 什么算「物理或数学类」

- 物理（含工程力学、材料力学、电路等物理分支）
- 数学（含线性代数、复变函数、微积分、概率统计）

判断依据是**课程与题目本身**，不是学校或学院名称。

## 手写答题纸图片的生成

本仓库不绑定特定字体，图片由你自己的渲染管线产出。只要满足：

- 尺寸接近 A4、300dpi
- 深色笔迹、米黄纸底
- 一问一页或按题分段

即可。常见做法有两种：

1. **字体渲染**：用一款手写体字体把答案渲染成图（快、可批量、字符无缺字）。
2. **笔迹合成**：采样本人手写生成字库，再用同一套渲染管线出图（更贴近本人字迹）。

无论哪种，出图后**必须亲眼看一遍图**再上传：字体缺字、公式错位、
行列没对齐这类问题只有看图才发现得了。

## 渲染时的换行（容易踩）

很多渲染管线会把源文本的换行丢掉，全部拼成一段再自动折行，
结果步骤挤在一起很难读。两条经验：

1. 源文本里**主动断行**，一行一步，段落之间留空行。
2. 折行是按**字符个数**算的，不是按像素宽度；
   含中英文混排时，一行的字符数要留余量（经验值 ≤30），否则会在词中间断行。

内容超过一页时拆成多页（标题标「(1/2)」「(2/2)」），
并确认每一页的末行都是完整的句子。
